## Current Architecture Notes

- `app/page.tsx` renders the main one-page portfolio and reads published Supabase projects when available, falling back to static content.
- `app/work/[slug]/page.tsx` renders a published project case study only when its Supabase flag is enabled and its database layout document validates; otherwise it returns not found.
- `components/Header.tsx` owns fixed header and mobile nav behavior.
- `components/PublicAnimations.tsx` progressively enhances authored `.reveal` blocks plus the four explicit `.reveal-item` stages inside project cards. Below-fold targets are prepared as paused animations after hydration, then played at the 94% viewport line through IntersectionObserver or a passive scroll fallback. Simultaneous entries are staggered, streamed descendants are registered through a MutationObserver, and a timeout restores canonical styles if WebKit interrupts completion. Admin routes have no marker, and reduced-motion preferences keep content static.
- `components/ContactForm.tsx` owns client-side form state and posts to `/api/contact`.
- `app/api/contact/route.ts` validates submissions with Zod, optionally inserts leads into Supabase with the server-only Supabase secret key, and sends email through Resend.
- `app/admin/` owns the protected admin dashboard, login, project CRUD, lead actionables, and settings routes.
- `components/ProjectCard.tsx` renders selected work cards from structured content.
- `components/ProjectVisitButton.tsx` renders the project arrow button for internal case-study links or external website links and calculates inner polygon values from a passed border width while preserving the original outer arrow geometry.
- `components/CaseStudyBackLink.tsx` gives case-study pages true browser-back behavior and synthesizes a `/#work` history entry before going back when a page was opened without prior history.
- `components/CaseStudyRenderer.tsx` renders the case-study hero and ordered layout document through controlled server-side primitives.
- `components/EddCalculationDiagram.tsx` mounts exactly one validated database-selected EDD composition. Database-owned breakpoint values select native HTML/CSS compact/mobile variants or authored tablet/desktop SVG variants; there is no device detection, screen-width heuristic, orientation handler, multiple hidden SVG tree, or project-specific diagram data in the component.
- `lib/content.ts` retains website-only project-card fallback data and homepage services; the obsolete static Delivery Intelligence case-study payload was removed after verified database promotion.
- `components/SystemVisual.tsx` renders simple CSS-based visuals for project cards.
- `lib/admin/` maps Supabase rows or static fallback content into admin/public screens.
- `lib/admin/authorization.ts` and `lib/admin/session.ts` enforce admin email authorization for route guards and mutating server actions.
- `lib/supabase/` owns Supabase config and browser/server/admin clients.
- `lib/content.ts` stores website-only selected-work fallback data and service content; its fallback projects never expose case studies.
- `lib/case-study/schema.ts` validates schema-versioned database layout documents.
- `app/globals.css` owns design tokens, layout, responsive behavior, and motion.
- `next.config.ts` authorizes `127.0.0.1` and the current LAN host for Next.js development resources so React hydration and HMR work when the dev server is bound for local-network testing.
