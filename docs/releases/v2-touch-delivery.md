# v2 touch delivery and lifecycle correction

The user reported delayed glow appearance on live, including later touches, while local appearance and movement responsiveness were fine. A separate report covered missing activation when touching during ongoing scrolling on both live and local.

Measured cold-contact appearance was 304ms in live Chromium (geometry HTTP completion285ms) and810ms in installed WebKit (HTTP509ms), versus28ms locally (HTTP7ms, worker2ms). Same-region repeats took11ms/57ms. These desktop-engine observations do not reproduce the user's exact seconds-long device wait, but isolate a contact-time network boundary. Expanding predecorated viewport surfaces was rejected: the evidence supports fetching plain geometry ahead, preserving existing raster dimensions/density and pixel ownership.

The delivery correction acquires one bounded visible-contact geometry selection before contact and refreshes its latest intent as the viewport changes. Coverage includes entire existing contact buckets at viewport edges, so the shared broker can fulfill their regional queries from cached paths. It does not create a glow, shell, mask or halo while idle; contact-time raster behavior, geometry, colors, density, worker and one-active/one-preparing ownership remain intact.

The input correction preserves a pending release/cancel before a new contact replaces the coalesced sample. Previously, two lifecycle events before one animation frame could overwrite the release, causing the new contact ID to be treated as a move belonging to the old gesture and rejected. The failing browser reproduction passes after the boundary correction in Chromium and WebKit; activation during browser smooth scrolling also passes. Movement samples and paint remain coalesced, and passive native-scroll/pinch behavior is preserved.
