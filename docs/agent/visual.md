# Visual and rendering requirements

Read before public CSS, layout, typography, motion, diagrams, PCB artwork, or SVG preparation changes. These exact constraints override generic skill suggestions; the approved PCB pointer lens is an explicit exception to the general ban on cursor effects. Generated PCB geometry is immutable: generic advice to simplify or reroute artwork does not apply to it.

## Visual Rules

The desired impression is cold competence: controlled, sharp, calm, confident, and not sterile.

Use:

- Near-black or deep-charcoal backgrounds.
- Slightly lighter surface layers.
- Soft off-white primary text.
- Muted cool-grey secondary text.
- Low-contrast borders.
- One restrained icy-blue, steel-blue, or desaturated-cyan accent.
- Typography-led hierarchy.
- Spacious but purposeful layouts.
- Subtle hover and reveal motion.
- Exposed public content uses proportional dark readability underlays that follow each rendered text line and fade softly to transparent well outside its curved edge; larger text receives a broader fade. Transparent secondary buttons use one underlay around the complete control. Do not add underlays beneath content already enclosed by an opaque surface.
- Hard-cornered buttons.
- Hard-cornered card surfaces with slightly thicker borders.
- Light-blue primary buttons with black text, an offset striped shadow shape, and a slightly larger/separated hover state.
- Button shadow shapes use solid deep colors with 3px borders and black diagonal negative stripes; do not make them translucent.
- Primary button hover states must keep black text.
- `Start a Conversation` uses the same primary button face with a pink striped shadow shape.
- Project `View Case Study` actions use a pointed arrow-style blue button with horizontal hover motion.
- Service item tags are plain inline text separated by large accent dots, not pills.

Avoid:

- Bright gradients.
- Neon cyberpunk styling.
- Decorative blobs.
- Fake terminal aesthetics.
- Code rain.
- Heavy glassmorphism.
- Multiple accent colors.
- Rounded pill buttons for primary actions.
- Rounded card surfaces.
- Pill-shaped service tags.
- Scroll-jacking, parallax, magnetic buttons, cursor effects, or long intro animations.

Every design choice should improve hierarchy, readability, comprehension, navigation, trust, or interaction feedback. If it does not, remove it.

## Rendering invariants

Force its generated text transparent and put the complete shadow layer at a negative stack level. Do not isolate individual underlay wrappers: all exposed content within one section content plane must share a stacking context so a later heading shadow also remains behind earlier siblings such as eyebrows. Put canonical content at a positive foreground level so shadow opacity cannot overlay or dim glyphs. `box-decoration-break: clone` gives the source each rendered line's rounded geometry. The source color must match the section's declared background color, including base, soft, surface, and blue impact sections. Preserve the current strengths of `0.91` for body/heading, `0.8372` for compact content, and `0.6006` for the transparent secondary-button source; these are the approved 30% increase over the preceding treatment. Extend the source beyond the content with a proportional zero-blur spread before applying the Gaussian blur; do not use padding for this extension, because it changes wrapping. Scope unrelated descendant and pseudo-element selectors to their actual component classes. Compact, body, and heading content use progressively larger source extension, radius, strength, and blur. Do not join a semi-transparent fragment fill to a separate shadow, use inset/outer edge shadows, or use a paragraph/layout-box pseudo-element. Keep all such sources in one behind-content stacking plane so overlapping halos never dim canonical content. Do not give an open-sided element a rectangular or outside-only enclosure shadow, and do not synthesize shadows along absent sides intended to remain flush with the background. When responsive CSS removes a border, remove its paint source too. Only fully bordered opaque enclosures—cards, diagram canvases, and form fields—use an outside-only shadow: use the surrounding section background color and the same approved strength, allowing the opaque fill to hide the inward half. Never use a generic black elevation shadow, attach either treatment to a broad positioning parent, animate these filters/shadows, create section-level foreground layers, or apply readability underlays inside an opaque surface that already hides the PCB artwork.
